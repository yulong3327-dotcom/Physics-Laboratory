# 联系资料、收货地址与讲义寄送

学生端以微信登录和自动注册为主，OpenID 只用于服务器识别账号。手机号和微信号是学生自行填写的联系资料，不是认证依据，不修改已验证登录手机号，也不会合并账号。短信未配置时不展示验证码登录入口。

## 使用方式

1. 后台编辑课程，开启“提供实物讲义寄送”，并在课程介绍中说明寄送范围、运费和规则。现有课程默认关闭，避免给已有订单增加未约定的实物服务。
2. 已付款学员在小程序“个人中心 → 收货地址”保存地址，在“讲义寄送”或订单入口提交寄送申请。每订单只允许一次申请，未付款或退款订单不能新建寄送或发货。
3. 后台“讲义寄送”查看收件信息，选择快递公司，填写实际快递单号和学生可见备注，再确认发货。此步骤记录已交寄包裹，不会预约快递员或扣除运费。
4. 学员在小程序查看快递单号和物流轨迹，收到讲义后确认收货。快递公司的签收状态与学生确认收货分别保留，不因查询而改动课程付款或寄送状态。

地址簿最多 20 个地址，仅有一个默认地址。寄送申请保存地址快照；修改或删除地址簿不会悄悄改变历史寄送地址。待发货时可以主动更换寄送地址，已发货不可改地址。后台可以取消待发货申请、恢复待发货，已收货记录不可再改物流资料。所有学生接口按当前登录账号检查所有权。

## 快递100真实查询配置

使用官方实时查询服务（[接口文档](https://api.kuaidi100.com/document/5f0ffb5ebc8da837cbd8aefc)）。在已开通查询服务且有查询额度的账号中取得 customer 授权码和 key，直接写入服务器私有 `.env`，不得写入小程序、网页、Git 或发到聊天中：

```dotenv
LOGISTICS_PROVIDER=kuaidi100
KUAIDI100_CUSTOMER=
KUAIDI100_KEY=
```

重启 `ZhikeCourse` 后，管理员访问 `/api/admin/logistics/config` 检查 `configured`。该接口只返回配置状态和支持的快递公司，不返回密钥。配置存在不代表账号查询产品已开通或额度充足，必须用自己实际寄送的一笔单号核对真实轨迹。

查询由后端请求 `https://poll.kuaidi100.com/poll/query.do`，使用官方 MD5 签名，10 秒超时，响应大小受限。仅在学生或管理员点击查询时调用，相同公司、单号和收件手机号合并请求，并缓存 30 分钟，遵守官方频率要求。缓存暂存于运行进程，重启会清除。小程序只访问原有课程 API 域名，无需把快递100密钥或 API 域名下发至学生端。

查询会向快递100传送运单号、公司编码及本次收件手机号，用于顺丰等快递的校验；小程序申请寄送弹窗已说明此用途。更新微信公众平台的隐私保护指引，写明联系方式、收件人和地址用于课程服务、讲义配送及物流查询，并在提交审核前核对平台要求。

未配置时查询返回 503 并明确告知，未查到轨迹时显示暂无记录；不会生成模拟物流。当前支持顺丰、京东、中通、圆通、申通、韵达、EMS、邮政、德邦和极兔。电子面单打印、预约上门取件及运费结算不在本版接口范围，需另开通对应寄件服务和寄件人信息。

## 发布与验收

运行 `npm test`、`npm run check:miniprogram:compile` 和 `npm run package:windows`。发布包包含 `student-services.js`、`logistics.js`；通过既有 `Update-Service.ps1` 在一致备份后更新生产服务，保留数据库、上传文件和凭据。

验收应包括：微信登录重入同一学员、手填信息可编辑、不同学员地址隔离、未付款不能申请、退款不能发货、地址快照不变、后台填写实际物流、学生查询真实轨迹及确认收货。开发测试使用隔离数据，不能把演示支付或本地测试单号当作真实成交或真实物流验收。
