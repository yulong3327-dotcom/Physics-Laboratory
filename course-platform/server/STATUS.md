# Backend handoff

Implementation complete in `server/`. `npm --prefix server start` listens on port 4310; `npm --prefix server test` covers the API and provider adapters. `web/dist` is served when present at server startup. Server requires Node 24+.

All API routes and exact fields in root IMPLEMENTATION.md are implemented. Success responses are direct objects/arrays; error responses `{message}`. Additional aliases support `/auth/sms/login`, `/auth/dev`, `/me/courses`, `/me/orders`, `/admin/overview`, `/admin/upload`, `/orders/:id/dev-pay`, `/lessons/:id`. `/auth/demo` body is optional. Demo admin: admin / admin123456.

User objects include `wechatLinked` (boolean, false for the demo identity). A phone-login user must safely associate WeChat before production WeChat Pay: `POST /api/me/wechat` with the current student Bearer token and `{code,phoneCode}`. Both values are exchanged against real WeChat APIs even when demo mode is enabled. The verified phone must match the current account's stored phone, any existing WeChat association must match the new openid, and neither identity may be owned by another account; conflicts return 409. Existing WeChat users without a phone can authorize a free phone only while proving the same openid. The response is the current user object, with no token or account switch; courses/orders remain attached to the same account. Missing credentials return 503, and no simulated association exists.

`GET /api/courses/:id` hides videoUrl for students; `/api/lessons/:id/play` is the access-checked playback endpoint. Uploaded video media requires short-lived signed URL; raw upload URLs are admin-only. Materials require enrollment and Authorization. Uploads are max 250 MB, allowlisted extensions; HTML/SVG/JS/executables denied. Material upload supports multipart file or JSON `{uploadId,title}`. Generic uploads return `{uploadId,id,url,name,fileName,size,mimeType,kind}`. The returned media URL is valid for lesson videoUrl. Lesson preview flags supported: isPreview/preview/freePreview. Course color/teacherTitle aliases supported. Draft and archived courses are hidden from catalog and prevent new purchases, but existing buyers retain course/library/playback/material access and historical orders. Empty lesson videos return a clear 404. New-user gift enrollment checks that the experience course still exists, is published and free.

Persistence: SQLite `server/data/courses.sqlite`; local private files in `server/data/uploads`. Six Chinese courses and six downloadable UTF-8 Chinese TXT handouts seeded; sample video is explicitly demo. Every student is given course-experience. SMS demo returns both devCode and demoCode, valid 5 minutes, 60 second retry, 5 attempts, one-time use. Tokens expire in 7 days and persist in SQLite; logout revokes.

Real capabilities: WeChat jscode2session + optional phone authorization code exchange; Tencent Cloud SMS SDK with an optional compatible HTTP adapter; WeChat Pay V3 JSAPI and Native request signing, wx.requestPayment params, notification certificate verification/decryption, merchant/app/trade-type/currency/amount validation and transactional idempotent settlement. Native payment creates a private QR URL for the browser checkout. No real account credentials exist, so production login/SMS/payment require platform credentials and configuration. Production rejects demo mode and requires a strong admin password/session secret. See server/.env.example and the root DEPLOYMENT.md for configuration. Pay notification URL: /api/payments/wechat/notify. Platform serial and cert are explicitly configured; certificate rotation must update configuration.

Verification: student SMS/login/order/ownership/access/download/progress/persistence/revocation; admin role isolation, CRUD/upload denial/private media/signatures/material download/archiving; production blank-catalog and credential checks; Tencent SMS SDK request mapping; Native checkout/callback handling; valid RSA-signed and AES-GCM-encrypted payment callbacks, bad signatures, mismatched amounts/payers, idempotence and replay transaction rejection.
