# AI 接口配置

本机开发使用 `.env.local` 配置服务地址及密钥，该文件禁止提交。生产服务读取平台环境变量，也支持服务器工作目录的 `.env`，已有环境变量优先。按照 `.env.example` 配置 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 后重启服务；具体步骤见 [部署说明](vibehub-deployment.md)。

模型设为 `gpt-5.5`，请求采用 `reasoning_effort: medium` 和 `max_completion_tokens: 12000`，不发送温度参数。识别请求使用 JSON 输出模式，图像使用 `detail: high`。不会静默降级到其他模型。OpenAI 官方模型资料确认其支持图像输入及 Chat Completions；第三方代理的实际支持需要单独验证。

本机代理的 JSON 模式还要求用户消息明确含有 `JSON`，仅系统提示包含该词会返回 400。客户端为全部结构化请求补充这一要求；代理错误会脱敏后显示具体原因。

官方资料：https://developers.openai.com/api/docs/models/gpt-5.5

浏览器仅调用同源接口：

- `GET /api/ai/status` 返回配置状态和模型名，不返回密钥。
- `POST /api/ai/chat` 接收 `messages`，由服务端附加固定模型及认证信息，转发到 `/v1/chat/completions`。

代理读取普通 `AI_*` 环境变量，不使用 `VITE_*`，因此密钥不会进入浏览器构建。开发与预览服务均绑定 `127.0.0.1`，请求限制为 8 MB、单次请求超时 150 秒。前端接受不超过 20 MB 的 PNG、JPEG、WebP；按比例限制最长边为 2400 像素，对透明区域铺白底，优先无损 PNG，超限才使用高质量 JPEG。

在“AI 导入”中输入文字描述或选择电路图片。图片先识别元件与导线，再用同一原图和候选结果复核端口与支路，因此每次图片识别会产生两次模型请求。复核失败保留首轮结果并显示待确认警告；文字导入只请求一次。重点区分电表量程、变阻器四端和导线交叉/汇合，不自动纠正原图接法。

所有 AI 结果均经过结构校验，使用 ELK 按拓扑排列元件，按两种视图的最大外框预留间距；布局失败时降级为无重叠网格。布局只修改坐标，不改变连接。工具栏“自动整理”可修复已有草稿并支持撤销。识别完成后查看数量和待确认项，点击“应用到画布”后替换当前电路；可撤销恢复原图。

简单串联回路采用上下两行的紧凑排列。空识别结果不会清空画布；关闭或取消弹窗会中止识别和后续复核请求。

`npm run preview` 可在本机预览构建并保留代理功能。生产使用 `npm run build` 后执行 `npm start`，由独立 Node 服务提供网页和同源 AI 接口。直接部署 `dist` 到静态托管只提供编辑器，AI 接口仍需要独立服务。

生产服务监听 `0.0.0.0` 和平台注入的 `PORT`（默认 8888），支持 HTTP/HTTPS 同源检查，可用 `PUBLIC_ORIGIN` 固定网站来源。默认每分钟最多 30 次 AI 请求、最多 4 个并发，可用 `AI_RATE_LIMIT_PER_MINUTE`、`AI_MAX_CONCURRENT_REQUESTS` 调整。计数在内存中，重启后重置；这些限制不是身份认证或计费额度管理，部署访问权限应由平台管理。

## 视频分镜请求

视频工作台使用同源 `purpose: video_storyboard` 请求。模型保持配置值，分镜使用 low 推理强度、7000 输出 token 上限和最长95秒单批请求。普通电路识别参数保持不变。文稿以600字或3句为阈值分批（单句不截断）；过慢或输出不完整会缩小当前批次，已完成进度保存在浏览器，可取消后继续。`AI_REQUEST_TIMEOUT_MS` 可设置普通请求超时（上限300000），视频分镜仍受95秒单批上限约束。

断点恢复不会保证上游服务不再超时；单句连续两次失败会保留进度并显示原因，重新生成可继续。分镜中的教学顺序、公式适用条件和旁白用词仍应在审核页确认。
