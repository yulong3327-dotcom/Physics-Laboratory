# 本机局域网运行

本机作为网页和 AI 接口服务器，其他设备通过同一 Wi-Fi／局域网访问。无需给访问者安装 Node 或复制项目。

## 启动和访问

1. 在项目根目录双击 `启动局域网服务.cmd`。首次使用需要本机已安装 Node.js 22.9 或更高版本，并已执行 `npm run build`；本机已完成准备。
2. 启动器在后台运行正式版本，生成根目录的 `局域网访问地址.txt`。把其中的局域网链接发给同一网络的访问者。
3. 本机可以双击 `打开电路转化器.url`。浏览器关闭不影响服务，双击 `停止局域网服务.cmd` 才会停止。

当前端口为 TCP 8888；2026-09-09 本机 WLAN 地址是 `http://10.250.32.128:8888/`。Wi-Fi 切换或路由器重新分配地址后，重新运行启动器读取新链接。

Windows 防火墙规则 `CircuitConverter-LAN-8888` 仅放行本地子网到本机 Node 程序的 TCP 8888 端口。没有公网入口。电脑必须保持开机、联网且不进入睡眠；电脑重启后重新双击启动。此版本不修改系统开机启动或电源设置。

## 工程、AI 与导出

每个浏览器各自保存草稿，访问者不会自动看到本机已有画布。分享电路请从本机导出 JSON，再让对方导入；不同设备不实时协同编辑。`127.0.0.1:5173`、`localhost:8888` 和局域网地址分别拥有独立浏览器存储，旧工程可用 JSON 迁移。

AI 配置从项目根目录 `.env`、`.env.local` 读取，`.env.local` 优先；密钥仅用于服务端向 AI 接口认证，不会发送给访问者。局域网启动器固定端口为 8888，并忽略部署平台的 `PUBLIC_ORIGIN`，使用同源接口。

素材、仿真、JSON、SVG、PNG 和 Manim 导出在浏览器内运行。HTTP 局域网视频导出使用浏览器支持的 MediaRecorder 兼容路径，导出期间保持页面在前台。本机使用 localhost 时也可使用 WebCodecs。

本次实际局域网验收中，桌面与手机视口的画布、仿真、SVG、PNG 和 Manim 导出通过；MP4 的 HTTP 兼容导出出现封装格式识别错误，尚未修复。WebM 本次未验收。不要把当前局域网链接视为已验证的视频导出环境。

更新源码后先停止服务，执行 `npm run build`，再启动。服务日志和进程记录位于 `artifacts/lan-service/`；停止脚本只停止经过项目绝对路径核实的服务进程。

## 无法打开时

- 先在本机打开 `http://localhost:8888/api/health`，应返回 `{"status":"ok"}`。
- 再核对 `局域网访问地址.txt`，手机或另一台电脑须连接相同局域网；访客 Wi-Fi、校园网或单位网络的客户端隔离可能阻止设备互访。
- 确认防火墙规则仍启用。更换 Node 安装路径或换电脑后需要重新配置仅限本地子网的入站规则。

服务不依赖开发工具持续打开，也无需运行 Vite 开发服务器。
