# 视频生产平台

平台以“人工审核内容，后台持续批量制作”为主流程。项目中心负责内容与版本，生产中心负责跨项目提交、观察队列、处理失败和交付。当前为单机服务，多项目排队执行；不是分布式渲染集群。

## 日常生产

1. 在 `/#video` 创建课程或导入题目，确认讲稿，生成并审核分镜。
2. 保存并确认当前分镜。改动讲稿、配音或画面后，需要重新确认受影响的版本。
3. 进入 `/#video/production`，选择“批量制作”。每批最多 50 个项目，可选择高清成片（1080p）或整片预览（720p）。
4. “选择可制作项目”选择已审核且空闲、当前规格尚未完成的项目；已有成片仍可单独勾选重做。待审核或已有任务的项目不可选择。
5. 加入队列后检查逐项回执。一个项目未就绪不会阻止其他项目提交。后台完成配音、时间轴、镜头绘制、整片合成与自动验收，关闭浏览器后继续运行。
6. “进行中”查看进度，“待处理”恢复临时失败或打开项目修正内容，“成片库”下载 MP4、SRT、工程包和验收报告。

批量提交绑定用户选择时的项目版本。提交时版本已变化会明确拒绝该项；成功入队后继续使用当时已审核的快照，后续编辑不会混入正在制作的视频。生成任务的结果需要在项目中查看与采用，平台不自动替代内容审核。

## 中断与重试

- 每批请求先保存，再逐项目保存制作任务与回执。批次使用固定提交 ID；断网或关闭页面导致响应丢失时，“重试原提交”沿用同一 ID，已完成任务也不会被重复创建。
- 服务重启恢复未完成批次与任务；队列按提交时间执行。一个损坏的任务或可选断点不应阻断其他项目的列表与执行。
- 继续任务使用原内容版本，执行前按当前渲染器重新计算缓存。程序升级后不会错误复用旧画面；完整且兼容的镜头继续复用，配音另按内容缓存。
- 内容错误和损坏的制作快照需要打开项目处理并重新确认；临时故障和取消任务可以继续。未通过验收的残片不会出现在可下载成片中。
- 服务端每个数据目录只允许一个实例。预检、预览与渲染共用受控媒体队列，避免多任务同时争用本机资源。
- Manim 的一次性媒体文件放在独立短路径，成功或失败后清理，避免 Windows 在较深的数据目录中生成超长内部路径；镜头缓存与验收结果仍保存在原数据目录。

## 数据和接口

默认数据目录为 `.video-data`，可由 `VIDEO_DATA_DIR` 指定。已有项目与版本在 `projects/`，生成任务在 `tasks/`，渲染任务与结果在 `jobs/`，批次提交记录在 `render-batches/`，可复用媒体在 `cache/`。迁移或备份时应保留完整数据目录。

| 接口 | 用途 |
| --- | --- |
| `GET /api/video/projects?view=summary&lifecycle=all` | 轻量项目目录，不下载完整素材 |
| `GET /api/video/tasks`、`GET /api/video/jobs` | 跨项目生成与视频任务 |
| `POST /api/video/render-batches` | 带固定 ID、输出规格和版本列表的批量提交 |
| `GET /api/video/render-batches/:id` | 获取或恢复已有批次回执 |
| `POST /api/video/jobs/:id/resume`、`cancel` | 原版本续作与取消 |

批量提交请求示例：

```json
{
  "id": "one-stable-submission-id",
  "kind": "final",
  "projects": [
    { "projectId": "approved-project-a", "expectedRevision": 3 },
    { "projectId": "approved-project-b", "expectedRevision": 7 }
  ]
}
```

回执中的 `status: completed` 表示该批**提交已处理完毕**，不表示视频制作完成。逐项 `jobId` 对应后续制作任务；逐项 `error` 说明未入队原因。同一 ID 的请求内容必须一致；其他内容会返回冲突。实际视频完成状态由各 `jobId` 查询。

## 可重复验收

```powershell
npm run build
npx tsx --test tests/video*.test.ts
npx playwright test e2e/video-production-center.spec.ts e2e/video-batch-production.spec.ts
.video-runtime/Scripts/python.exe -X utf8 scripts/check-video-platform.py
npx tsx scripts/check-video-platform-batch.ts --long-path-test
```

平台渲染矩阵在独立目录使用真实 Manim、FFmpeg、字幕、解码和成片验收。覆盖双角色板书、公式卡片、电路标注、剧情图运动、总结转场、新缓存、复用缓存、布局变更、坏缓存重建和失败阻断。音轨由测试替身生成，不访问线上配音服务，也不代表真实音色、AI 内容准确性或供应商可用性通过。

2026-09-21 验证记录：327 项视频单元与服务测试、18 项桌面/移动浏览器用例通过；Python 核心 117 项通过；真实渲染矩阵 14 个场景、69 项检查通过。短路径修复后再次完成全部矩阵（运行 `20260921T045759-4392`）：五类项目首次制作合计 63.296 秒，缓存复跑合计 11.844 秒，本机本次约快 5.34 倍，不作为其他机器或在线配音的耗时保证。

HTTP 批次实测在隔离服务中创建项目并完成审核，同批提交两份不同已审核工程和一份未审核草稿。两份工程依次经过真实 Python、Manim、FFmpeg 和验收输出 720p 视频，草稿单独拒绝；文件下载、范围播放、同批重试不重复渲染全部通过。较深目录复测 71 项检查通过，报告位于 `artifacts/video-platform-batch-acceptance/latest.json`。新增短路径回归后，相关 Python 生产恢复测试 11 项全部通过。

实际工作台的桌面、移动端和成片库已做只读浏览器检查，报告位于 `artifacts/video-platform-live-ui/report.json`，没有提交或修改用户项目。线上配音只由已有正式课程提供验证证据；批次和矩阵的可重复检查均明确使用测试音轨。

此外，已确认的《电路的三种状态》第 6 版保留原 Edge 双人音色，23 镜头正式制作通过，285.75 秒、1920×1080、24 fps，报告在 `artifacts/render-fix-2026-09-21/final/`。这项实测补充真实配音证据；平台能力主要由多项目恢复测试和内容矩阵验证。自动报告中的 `humanReview: pending` 仍需人工完成教学与听审。

## 当前边界

跨项目队列由本机持久化服务管理，浏览器只负责编辑与操作。当前未加入多租户隔离、多人角色权限、分布式渲染、自动发布或定时发布。任务分页目前在浏览器进行，适合现阶段本地课程生产；大量历史任务时仍需后续服务端分页。Fish、Azure、Edge 的在线可用性依赖所选服务，生产不会自行更换音色或用测试音轨代替。
