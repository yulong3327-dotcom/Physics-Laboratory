# 视频渲染恢复与端到端验收（2026-09-21）

本次交付已扩展为“人工审核后持续批量制作”的平台流程，包含跨项目生产中心、持久批次、队列恢复和成片库。平台入口、操作、接口与多项目验收见 [视频生产平台](video-production-platform.md)；下文保留渲染故障与真实课程的验证记录。

## 修复的问题

最近的预览和正式成片任务均有 23/23 镜头失败：生产循环跳过预检后，直接读取尚不存在的 `timeline.json`。即使人工提前生成时间轴，合成函数也跳过了自动验收与通过回执，无法满足服务端完成条件。

恢复必需的制作依赖：逐镜头检查完整缓存；缺失时完成静态检查、真实配音、字幕和时间轴，再绘制；按原顺序合成全部镜头；完成自动验收后才提交结果。失败镜头不会阻止其他独立镜头保存，也不会被静默丢弃生成短片。

实际跑完整课时另发现竖向导线被横向箭头宽度限制拒绝。现在窄竖线可生成竖向电流箭头，保留电路几何与原有旁白；标注避让仅处理实际重叠的标签，避免被其他支路名称推离目标。

## 效率与稳定性

- 完整镜头按静态、音频、时间轴、视频完整性标记复用。真实失败恢复复用了 22/23 镜头，只制作缺失的一镜，然后重新合成验收。
- 静态检查和正式绘制共享完整公式 SVG；每次编译在独立目录执行，损坏缓存重新生成，防止 Manim 清理其他进程的中间文件。
- 合成片段优先硬链接，跨盘回退复制；长音轨分块拼接 PCM，再统一编码 AAC，保持固定帧率及字幕时间基准。
- Manim 中间视频使用独立短临时目录，完成或失败后清理；真实批次深目录回归通过，避免其内部多层路径超过 Windows 限制。
- 中文日志采用跨块 UTF-8 解码，末尾没有换行的错误事件也会处理；子进程退出后关闭日志管道。
- 成片回执与实际验收报告均须通过，报告的项目与版本须匹配。已提交产物的任务在服务重启时直接恢复完成状态；不完整输出仍恢复制作。

## 复验方式

启动工作台并确认当前讲稿、分镜，使用本地配置中的 `AI_API_KEY` 登录。脚本通过真实 HTTP 接口提交渲染并轮询，核对全部镜头、验收报告、MP4、字幕下载和分段读取。不会替用户确认讲稿或改用其他配音。

```powershell
node scripts/verify-video-render.mjs --project=<项目ID> --kind=final --out=artifacts/render-e2e
node scripts/verify-video-render.mjs --job=<任务ID> --resume --out=artifacts/render-e2e-recovery
```

`--origin` 可指定工作台地址，默认 `http://127.0.0.1:5173`；`--timeout-minutes` 默认 60 分钟。`--job` 单独使用只检查已有任务，搭配 `--resume` 才继续失败或取消的任务。脚本不输出密钥或会话 Cookie。
