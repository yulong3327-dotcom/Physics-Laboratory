# 视频稳定生产与恢复

工作台采用“保存草稿 → 确认讲稿 → 后台规划 → 调整并确认分镜 → 全课预检 → 绘制合成 → 自动验收 → 输出”。题目和普通讲稿共用该流程。原 `VideoProject`、声明式分镜、Manim 场景、人工布局与正式双人音色保留。

## 使用流程

1. 在文稿页保存题目或讲稿。编辑原稿可以立即保存，不要求先生成分镜。
2. 题目先提交“生成解析讲稿”；老师核对条件、答案和双人台词，再确认讲稿。普通讲稿也需明确确认。
3. 提交后台分镜任务。系统先固定章节、台词归属和共享电路 ID，再按默认 6 段/1000 字请求细化；一次请求可包含多个教学段，每个镜头严格保持自己的章节和电路归属。关闭页面后任务继续，重新打开可查看进度、断点和结果。
4. 核对分镜画布、物理数据及同步点。生成结果只在基准版本仍适用时采用；存在更新时展示差异和冲突。人工编辑保留在当前版本。
5. 确认分镜，准备全课配音与时间轴。先检查全部镜头的引用、公式编译、高亮定位、对象出现/替换关系和教学数据，再合成全部旁白并验证真实事件时间。任何内容错误都会阻止长时间绘制。
6. 用“配音与事件预览”听音频、拖动播放位置或跳转事件。它显示同一真实时间轴在该时刻的对象状态，不包含 Manim 动画插值；完整运动效果仍用镜头视频验收。
7. 提交镜头预览、整片预览或成片。渲染会为缺少完整缓存的镜头自动执行静态检查、配音与时间轴准备，无需靠一次之前的预检碰巧留下文件。完整镜头按校验标记复用；某镜头失败时保留其他镜头，缺镜头不合成残片。只有视频解码、尺寸帧率、字幕/台词完整性、事件覆盖和音轨偏移验收通过，任务才标记完成。

旧工程可以打开、编辑和下载已有视频。旧的审核勾选值不能替代新的讲稿和分镜确认。讲稿变更会让下游过期，此前分镜保存在版本历史；已完成成片仍可查看。

## 局部修改

在镜头助手输入“这页拆成两步”“答案讲到这里再出现”等要求，并选择修改范围。AI 只能提交受限分镜建议，不得改写已确认旁白、角色与正式音色。应用前查看前后画面和差异；采用后可撤销该次操作。

镜头与对象可以锁定。默认保留范围以外的镜头、手动布局和锁定对象。共享电路需要局部变化时复制为新素材，不覆盖全课共用素材；采用时服务端再次检查当前版本和新加的锁。

同步关键词支持指定第几次出现。对象内高亮词的出现次数与旁白同步词的出现次数是两个独立字段。AI 输出中“得到 P=24W”比目标“P=24W”早出现的包含词组，可在生成解析时对齐目标的同次出现并留下审核备注；真正跨步骤的错误仍需修改内容。

## 版本与故障恢复

- 草稿、讲稿确认指纹、分镜确认指纹分别保存。修改原文/台词会撤销讲稿和下游确认；只改布局会撤销分镜确认。
- 任务和渲染绑定 `expectedRevision`。缺少渲染版本返回 428，旧版本返回 409。迟到结果独立保留，三方合并发现同字段冲突时返回 409，显式查看后才可采用冲突结果。
- 同一结果只采用一次。服务端在串行修改区重读采用回执；若服务死在工程写入与回执写入之间，由已提交的版本历史恢复回执。
- 网络中断、429、5xx 由服务端传输层最多请求三次，遵守 `Retry-After`。仍失败进入等待继续状态；分镜批次不会再叠加网络重试，也不切换配音服务或音色。
- 明确的分镜请求超时直接交给批次缩小，一组台词最多因超时拆一层；输出截断可继续二分到单段。断点保存拆分边界，恢复不会再次扩大请求树。鉴权、429 和 5xx 耗尽不会触发拆批。
- 新分镜在每批提交前通过生产字段/公式/板式检查及已生成前缀的教学检查。镜头与对象定位也用于修复旧断点，避免把整课坏结果反复复用。每次请求的耗时、输入/输出体量与 token 用量保存在 `metrics.calls`，内容纠正计数与网络重试分别记录。
- 新生成的 AI 分镜若被校验器标记为 `storyboard_content_invalid`，系统会将具体错误反馈给模型，在同一隔离批次内最多修正两次（含首次共三次输出）。每次沿用已确认的台词原文、顺序和 ID，保留已完成批次；仍不通过时保留最终错误、候选分镜和断点供检查。原工程校验、全课结构约束、预检以及其他未分类内容错误仍直接阻止后续制作，不保证自动修正成功。
- 修正生成器后重新提交相同版本和输入的分镜任务，默认继承最近失败任务的合法断点，再由生成器复核后继续。原任务及失败证据保留，不会自动恢复失败任务。显式 `force: true` 从头开始，其他类型任务不继承失败断点。
- 关闭浏览器不取消后台任务。服务启动自动恢复未完成任务与渲染快照；显式取消的任务不会自行恢复。
- Windows 进程树使用内核 Job Object 和父进程监测，期限或取消时终止关联组件；即使服务/解释器硬退出，也清理后代进程。媒体队列可以继续执行下一任务。
- 缓存使用临时文件、原子替换、完整性标记与 SHA-256。坏镜头或坏音频副本只影响依赖它的步骤；已验证的共享配音片段继续复用。
- 公式编译使用独立临时目录，只共享完整 SVG，避免并发清理彼此的中间文件。镜头合成优先使用硬链接，跨盘回退复制；配音采用流式 PCM 拼接并统一编码，保持字幕和音轨对齐。
- 成片完成回执和验收报告均须存在且通过，工程 ID、版本必须匹配。服务中断发生在产物已提交、任务状态尚未提交之间时，重启可直接恢复完成状态。
- 窄竖向导线支持竖向电流箭头：正向朝上，反向朝下；“上方”放在线左侧，“下方”放在线右侧。横向箭头仍按向右、向左表示。
- Fish 在同条台词内部使用最多 2 路独立片段请求，按原文顺序拼接实测音频。429/暂态故障统一退避并降为串行；失败停止后续请求，已成功片段仍可恢复。`VIDEO_TTS_CONCURRENCY=1` 可使用单路。旧缓存与正式双人音色保留。

存储在 `VIDEO_DATA_DIR`（默认 `.video-data`）。项目版本位于 `projects/<id>/revisions/`；后台任务位于 `tasks/<id>/`，包含 `input.json`、`checkpoint.json`、`result.json`、`task.json`；渲染位于 `jobs/<id>/`。JSON 写入先刷新文件再原子替换。同一目录只允许一个服务实例，不要让开发和生产服务同时使用同一目录。

缓存依赖按内容计算：布局只重做相关镜头；台词、发音或音色变化重做对应音频和时间轴；模板或渲染器变化使相关画面缓存失效。分镜审批过期与缓存失效是独立概念，重新确认不会强制重配所有音频。

## 接口

以下接口都在 `/api/video` 下：

| 接口 | 用途 |
|---|---|
| `POST projects/:id/approve-script` | `{ expectedRevision }` 确认讲稿 |
| `POST projects/:id/approve` | `{ revision }` 确认分镜 |
| `POST projects/:id/tasks` | `{ expectedRevision, kind, scope?, instruction?, force? }` 创建任务 |
| `GET tasks?projectId=...` / `GET tasks/:id` | 列表、进度、结构化错误 |
| `GET tasks/:id/result` | 获取独立任务结果和建议 |
| `POST tasks/:id/resume` / `cancel` | 从保存断点继续或取消 |
| `POST tasks/:id/apply` | `{ expectedRevision, acceptConflicts? }` 采用结果 |
| `GET projects/:id/revisions/:revision` | 查看过去版本 |
| `POST projects/:id/render` | `{ expectedRevision, kind, shotIds? }` 提交版本绑定的制作任务 |
| `GET tasks/:id/timeline/:shot` | 真实时间轴；后缀 `/audio` 获取音频，`/frame?time=秒` 获取对象状态 |
| `GET jobs/:id/files/validation.json` | 成片自动验收报告 |
| `GET jobs/:id/nodes` | 每个镜头的状态、缓存命中与错误 |
| `POST jobs/:id/resume` | 从原制作快照继续失败或已取消的任务，复用完整镜头 |
| `GET jobs/:id/keyframes/:name.png` | 镜头关键帧 |

任务类型为 `problem_script`、`storyboard`、`storyboard_patch`、`preflight`。重复请求按输入快照、版本和范围幂等。界面默认复用同版时间轴任务；再次提交返回 `waiting_retry` 时会显式继续原任务。API 的 `force: true` 可明确创建新检查任务，媒体缓存仍可复用。

`ValidationIssue` 含阶段、镜头、对象、错误码、严重程度和是否可重试。预检内容错误用于定位并修改，网络错误用于断点继续。`GenerationTask` 与 `StoryboardPatch` 类型定义见 `server/videoTypes.ts`。

## 阶段期限

| 配置 | 默认 |
|---|---:|
| `VIDEO_AI_REQUEST_TIMEOUT_MS` | 95 秒/请求 |
| `VIDEO_GENERATION_TIMEOUT_MS` | 30 分钟/生成任务 |
| `VIDEO_JOB_TIMEOUT_MS` | 2 小时/预检或渲染进程 |
| `VIDEO_PREVIEW_TIMEOUT_MS` | 120 秒/画布预览 |
| `VIDEO_STATIC_TIMEOUT_SECONDS` | 120 秒/镜头静态检查 |
| `VIDEO_MANIM_TIMEOUT_SECONDS` | 600 秒/镜头绘制 |
| `VIDEO_VALIDATION_TIMEOUT_SECONDS` | 600 秒/成片验收 |

配音请求有 180 秒期限；音频格式转换 120 秒；其他 FFmpeg 步骤默认 600 秒。进程长时间运行每 15 秒报告存活，阶段切换记录耗时。配音请求重试记录次数与等待时间。总任务期限同时约束网络等待和子步骤。
