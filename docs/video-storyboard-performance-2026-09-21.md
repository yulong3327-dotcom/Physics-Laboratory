# 分镜生成稳定性与耗时验证

本次直接修改现有分镜生成流程，没有增加项目中心或新的生产入口。

## 已落地

- 原来整课一次请求改为默认每批最多 2 段、最多 3 个请求并行。每批共享整课原文上下文，生成和校验只覆盖当前台词。
- 每批验证后单独落盘并显示；服务重启、超时或内容错误后只补缺失批次。旧版完整断点仍可读取。
- 超时或输出截断自动缩小当前批次，不重复请求已完成部分。不可继续拆分的超时保留为可恢复任务；没有无限重试。
- 内容错误最多带校验反馈纠正一次。取消信号传入每个实际请求，写盘失败后停止派发。
- 公式、镜头和电路按批次隔离 ID，所有关联同步迁移，合并后按原台词顺序完整校验。
- 精简输出只省略可由系统确定的默认字段，必要画面、公式、同步词和审核提示仍要验证。
- 常见纯电阻串联、并联可由 AI 明确选择短模板及参数，系统展开标准接线；复杂图和原题图仍沿用完整图协议。缺少数值时不会填猜测值。
- 预览按镜头 ID 和内容缓存，仅准备新增或修改的画面；较早批次迟到不会清空已完成预览。

默认参数可通过服务配置调整：`VIDEO_STORYBOARD_BATCH_UTTERANCES`（默认 2，最大 8）、`VIDEO_STORYBOARD_CONCURRENCY`（默认 3，最大 3）。本次未增加 95 秒请求时限，也未更换用户配置的模型和凭据。

## 真实请求证据与边界

输入是现有项目 `video-7842d4fb-eff1-4232-a0cc-01bde9262c68` 的已确认快照，50 段台词。测试使用独立 benchmark 身份和 artifacts 目录；没有覆盖用户工程、人工审核状态或启动自动渲染。

| 验证 | 结果 |
| --- | --- |
| 修改前的真实任务 | 单请求 95,021 ms 后超时，0 张画面 |
| 初次增量方案（当时 3 段、2 并行） | 首批有效画面 43,644 ms，后续部分大请求仍超时 |
| 精简协议 + 2 段、3 并行续跑 | 26,616 ms 得到新画面；约 75,860 ms 从 35 段推进到 44 段 |
| 复杂电路段 | 完整图协议多次 95 秒超时；最终使用标准串联模板，一次请求 60,514 ms，通过校验 |
| 最终结果 | 50/50 原台词、41 个分镜；结构、覆盖顺序、公式同步、电路及画面准备均通过 |
| 重启恢复 | 49 段已完成时仅请求剩余 1 段；成功结果没有重新生成 |
| 乱序预览（可重复测试） | 六张画面准备调用从 12 次降至 3 次；完成数为 0→2→4→6 |

这是开发过程中多次恢复后的完整验收，不是最终版本从零开始的一次整课耗时基准。不能把最后 62 秒的补做时间当成 50 段总生成时间，也不能据此保证上游不会超时。上游单请求仍存在几十秒波动；现在波动影响当前批次，已完成结果可以保留复用。

机器报告：`artifacts/storyboard-latency-fixed/report.json`；完整测试结果：`artifacts/storyboard-latency-fixed/result.json`。报告包含历次迭代累计请求指标，成功最终单次补做为 1 个请求。

## 回归

388 项视频相关测试通过，包括并发上限、精简协议、标准电路仿真、断点恢复、取消、内容错误、引用隔离、预览和既有生产流程。生产构建通过。
